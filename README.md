# Claude Virtual Agents

Claude Code のセッション(メインエージェント + サブエージェント)の動作を、**キャラクターが動く宇宙軍事基地風の2Dアニメーション**としてリアルタイム可視化するWebアプリです。

- メインエージェント = ボス、サブエージェント = 社員というメタファー
  - ボスも社員も**球体マスコット型(ハロ型)のロボ**として描かれます。ボスだけが**白と青のツートン + 両手両足**を持つので、手足の有無でひと目で見分けられます。社員は起動順に割り当てられる担当色(8色)とネームプレートで区別できます(担当色は**掲示板の行頭の丸**と**足元の札の丸**に出ます。プロジェクトを複数同時に動かしているときは、社員の球体そのものは**上司であるボスと同じ色**になります。下記「複数のプロジェクトを同時に見る」)
  - **ネームプレートの背景は全員白**、文字は黒です
  - 社員の頭の上には**勲章**が付きます。**個数がモデル**(Fable 3 個 / Opus 2 個 / Sonnet 1 個 / Haiku・モデル不明は無し)、**色がエフォート**(low ブロンズ / medium シルバー / high ゴールド / xhigh ルビー)です。リモートモードでは名前の右に出ます
- 各エージェントはツール実行に応じてオフィス内の「部屋」を移動し、動作に応じたポーズを取ります
  - Read / Grep / Glob、Bash → **オペルーム**で端末操作(右端の縦長コンソールに向かって**横向きで縦に並びます**。先頭がボスで、4人目からは手前に列が増えます。ボスが2体以上いるときだけ2体目が手前の列に回ります)
  - Write / Edit → **データバンク**で資料を書き込む
  - Bash のうち **`git` のコマンド** → **司令席**でコミット・push(頭上に **GIT**)
  - Bash のうち**リモート接続**(`ssh` / `scp` / `sftp` / `rsync` / `kubectl` / `gh` / `docker -H`)→ **通信管制室**でラックを操作
  - WebFetch / WebSearch → **観測ブリッジ**で舷窓の外を見る(窓を向くので背中が見えます)
  - E2E(ブラウザ操作の MCP / Playwright・Cypress などを叩く Bash)→ **観測ブリッジ**で画面を覗く(頭上に **E2E**)
  - サブエージェントが仕事を終えると、**司令席**へ寄ってメインエージェントへ報告(頭上に DONE)してから退室します
  - 手が空くと**充電ステーション**へ、入室は入口の**カタパルト**からの射出
- 吹き出しで現在のタスク内容を表示します
- 壁の掲示板に、1行1人で **名前 / 所属プロジェクト / 作業 / モデル / 経過 / トークン** を表示します
  - 「作業」は**委譲されたときの指示(作業タイトル)**で、個々のツール実行では上書きされません。吹き出しが消えたあとでも「誰が何のために動いているか」が分かります。細かい作業内容は吹き出しと頭上のチップで分かるので、掲示板はタイトルを長く出す方に振っています(メインエージェントは依頼を持たないので、直近のツールが入ります)
  - 「所属」はプロジェクトを複数同時に動かしているときだけ出ます(1つだけなら列ごと畳まれます)
- Claude Code 本体には非侵襲(Hooks 設定の追加のみ)で、すべて `127.0.0.1` 上で完結します(外部通信なし・DB なし)

詳細な設計は [DESIGN.md](./DESIGN.md) を参照してください。

> [!TIP]
> git や Node.js、ターミナルの操作に慣れていない方は、[はじめてのセットアップガイド(GUIDE.md)](./GUIDE.md) から始めてください。ZIP でダウンロードする方法で、インストール・起動・画面の見方を順に説明しています。

## セットアップ

git を使わずに ZIP で入れる手順や、Node.js の入れ方は [GUIDE.md](./GUIDE.md) にあります。

### Windows(PowerShell)

```powershell
git clone https://github.com/ryukyuhub/claude-virtual-agents.git
cd claude-virtual-agents
npm install
npm run setup-hooks   # ~/.claude/settings.json に Hooks を自動追記
npm start             # サーバー起動
```

ブラウザで `http://127.0.0.1:3777` を開いてください。

- セットアップスクリプトが `C:\Users\<name>\.claude\settings.json` を自動で編集します(手書き編集は不要。内容が変わるときだけ、編集前に `settings.json.bak-YYYYMMDD-HHMMSS` としてバックアップされます。既存のバックアップは上書きしません)
- サーバーは `127.0.0.1` にのみ bind するため、Windows ファイアウォールの警告は表示されません

### macOS(ターミナル)

```bash
git clone https://github.com/ryukyuhub/claude-virtual-agents.git
cd claude-virtual-agents
npm install
npm run setup-hooks   # ~/.claude/settings.json に Hooks を自動追記
npm start             # サーバー起動
```

ブラウザで `http://127.0.0.1:3777` を開いてください。

### セットアップスクリプトの注意

- すでに設定済みで変更が無いときは、`settings.json` に書き込みません(バックアップも作りません)
- 書き込みは一時ファイルに書いてから置き換えるので、途中で落ちても `settings.json` が半端な中身になりません。`settings.json` がシンボリックリンク(dotfiles の管理など)なら、リンクは残したまま実体の側を書き換えます。書き換えても元のファイルの権限はそのまま引き継がれます(Windows では ACL までは引き継がれません)
- `settings.json` が正しい JSON でない・形が想定と違う(`hooks` がオブジェクトでないなど)ときは、**何も書かずに中止します**。手で直してから再実行してください
- リポジトリの場所(パス)に `"`・バッククォート・`$`・`%`・`!`・改行・NUL(Windows 以外では `\` も)が含まれていると、インストールを拒否します。Hook のコマンドはシェルが解釈するため、これらの文字があるとコマンドが壊れたり別のコマンドとして実行されたりするからです。その文字を含まない場所(例: ホームディレクトリ直下)に clone し直してください
- Windows で **UNC パス(`\\server\share\…`)にリポジトリを clone した場合**も、インストールを拒否します。Hook がツール呼び出しのたびにネットワーク越しに `node` を起動することになり、共有に届かないときは Hook がそのたび失敗するためです。ローカルのドライブに clone し直してください

### 動作確認

1. サーバーを起動した状態で、Claude Code で適当なタスクを実行します
2. ブラウザ上のオフィスでキャラクターが部屋を移動し、吹き出しが表示されれば成功です

### アンインストール(Hooks の削除)

```
node setup-hooks.mjs --remove
```

追記した Hooks 設定だけが削除され、既存の設定はそのまま残ります(同じエントリに同居している他の Hook も残ります)。

- 削除の対象は、**いまのリポジトリの場所から生成したコマンドと完全に一致する Hook だけ**です。**リポジトリを移動した後は**、移動前の場所で `--remove` を実行するか、`~/.claude/settings.json` から手で消してください(移動後の場所で実行しても、古い場所を指す Hook は見つかりません)
- 移動前の場所を指す Hook が残っていると、インストール時(追記)にも `--remove` 時にも警告として一覧が表示されます。放っておくと報告が二重になったり Hook が失敗し続けたりする原因になるので、案内に従って手で消してください(自動では消しません)

## 設定(.env)

ポート番号とメインエージェントの呼び名は `.env` ファイルで変更できます。**これが推奨の方法です。**

```powershell
# Windows (PowerShell)
copy .env.example .env
```

```bash
# macOS / Linux
cp .env.example .env
```

作成した `.env` を編集します。

```ini
# 待ち受けポート(既定: 3777)
CVA_PORT=4000

# メインエージェントの呼び名(既定: BOSS)
CVA_BOSS_NAME=社長

# 手が空いたと見なすまでの秒数(既定: 60)。これを過ぎると充電ステーションへ
CVA_IDLE_SEC=60
```

`npm start` で反映され、起動ログに読み込んだキーが表示されます。

```
.env を読み込みました: CVA_PORT, CVA_BOSS_NAME
Claude Virtual Agents server: http://127.0.0.1:4000
メインエージェントの呼び名: 社長
```

`.env` は Git 管理外(`.gitignore` 済み)なので、各自の環境設定をリポジトリに含めずに済みます。

### なぜ .env が推奨なのか

**サーバー・Hook レポーター(`report.js`)・テストスクリプトがすべて同じ `.env` を読む**ためです。ポートを変えても Hook 側に自動で反映されるので、設定のズレでイベントが届かなくなる事故が起きません。

`.env` はこのプロジェクトのディレクトリを基準に読まれます。Hook はユーザーが開いている任意のプロジェクトをカレントディレクトリとして実行されますが、その影響を受けません。

### 設定の優先順位

**コマンド引数 > 実際の環境変数 > `.env` > 既定値**

`.env` はあくまで既定値の位置づけなので、その場限りの上書きがいつでも可能です。

```powershell
# Windows (PowerShell)
npm start -- --port=4000 --boss=社長
$env:CVA_PORT="4000"; npm start
```

```bash
# macOS / Linux
npm start -- --port=4000 --boss=社長
CVA_PORT=4000 CVA_BOSS_NAME=社長 npm start
```

| 設定項目 | 環境変数 / `.env` | コマンド引数 | 既定値 |
| --- | --- | --- | --- |
| 待ち受けポート | `CVA_PORT` | `--port=4000` | `3777` |
| メインエージェントの呼び名 | `CVA_BOSS_NAME` | `--boss=社長` | `BOSS` |
| 充電に入るまでの秒数 | `CVA_IDLE_SEC` | `--idle=10` | `60` |

ポート変更後は `http://127.0.0.1:4000` を開いてください。ビューアーの WebSocket 接続先は配信元のポートに自動追従します。不正なポート値(数値でない、1〜65535 の範囲外)を指定した場合は警告を表示して `3777` にフォールバックします。

### メインエージェントの呼び名について

呼び名はブラウザ側からも上書きできます(URL パラメータが最優先)。

```
http://127.0.0.1:3777/?boss=部長
```

全体の優先順位は **URL パラメータ > `--boss=` 引数 > 環境変数 > `.env` > `BOSS`** です。

モックプレビュー(アーティファクト / artifact-preview.html)では「表示設定」の入力欄からリアルタイムに変更できます。

### サブエージェントの名札

カスタムサブエージェント(`.claude/agents/` の定義)が起動されると、名札に表示名が出ます。Claude Code のエージェント定義名(`name:`)は英小文字とハイフンのみなので、日本語で呼びたい場合は表示名を別に指定します。

**方法1(おすすめ): 定義ファイルに書く**

`.claude/agents/<定義名>.md` の frontmatter に `displayName:` を足します。定義とセットで持ち運べるので、定義ファイルを見れば名札が分かります。

```yaml
---
name: sayla
displayName: セイラ
model: haiku
---
```

**方法2: `.env` で上書きする**

定義ファイルを書き換えずに変えたい場合(他人のリポジトリの定義など)は `.env` に書きます。こちらが最優先です。

```ini
# .env
CVA_AGENT_NAMES=sayla:セイラ,my-agent:調査班
```

優先順位は **`CVA_AGENT_NAMES` > 定義ファイルの `displayName:` > 組み込みの対応表 > 定義名そのまま** です。組み込みの対応表には既定でガンダムシリーズの名前が入っています。

| 定義名 | 既定の表示名 | | 定義名 | 既定の表示名 |
| --- | --- | --- | --- | --- |
| `amuro` | アムロ | | `char` | シャア |
| `ryu` | リュウ | | `kai` | カイ |
| `mirai` | ミライ | | `bright` | ブライト |
| `sayla` | セイラ | | | |

Claude Code の**組み込みエージェント**(`.claude/agents/` に定義ファイルが無いもの)には、上の名前と重複しない別の名前を割り当てています。カスタムのエージェントと同時に動いても名札で見分けられます。

| 定義名 | 既定の表示名 | 由来 |
| --- | --- | --- |
| `Explore` | ミハル | 情報を探る密偵(探索・検索) |
| `Plan` | レビル | 作戦を立てる司令官(参謀) |
| `general-purpose` | フラウ | 何でもこなす万能役(汎用) |

どこにも指定が無い定義名は、その定義名がそのまま名札に出ます。表示名は 24 文字までで、それ以上は切り詰められます。すぐ使えるサンプル定義は [examples/agents/](./examples/agents/) にあります。

定義ファイルの `displayName:` は**サーバーを起動したまま書き換えても次のイベントで反映されます**(再起動は不要です)。

### 表示モード: オフィス / リモート

2つの表示モードがあります。

- **オフィスモード(既定)** — 全員が1つのオフィスにいて、ツール実行に応じて部屋を移動する
- **リモートモード** — 全員がビデオ会議に参加している見立て。1人が1枚のタイルになり、**左にカメラのバストアップ、右にそのエージェント自身の情報**(名前・作業バッジ・モデル/エフォート・経過時間・トークン・直近の動き2行)が並びます
  - 誰かのタスクが変わるとそのタイルの枠が緑に光ります(ビデオ会議のアクティブスピーカー表示)。ボスが2体以上いるときも、どちらの部下かは**カメラに映る球体の色**で分かるので、枠は「いま話している人」だけを示します
  - ヘッダーの右端に「参加 N 名」が出ます。参加・退出のトーストは画面左下に出ます
  - **縦表示(既定)**: タイルが1列に並びます。BOSS が常に先頭(最上段。複数プロジェクトのときは BOSS が人数ぶん先頭に並びます)。BOSS が2体以上いるとき、サブは**親の BOSS ごとにまとまって**並びます(同じ BOSS の部下が続けて並ぶので、どの BOSS に何人付いているかが上から順に読めます)
  - **横表示**: 参加人数に応じて2〜3列に並びます。BOSS が常に先頭(左上)。こちらはサブが入室順のまま並びます(横は列の間隔が段の間隔より広く、番号順に並べても隣り合わないため)
  - 参加者が増えるとタイルが自動で詰まり、狭くなると「直近の動き → 経過/トークン → モデル」の順に情報が省かれます(8人程度までは全部出ます)
  - 以前あった大きな共有画面(全員の一覧・活動ログ・下部のバー)は廃止しました。**全体の活動ログとセッションのターン数は表示しません** — どのタイルにも属さない情報のため。「誰が直前に何をしたか」は各タイルの直近の動きで分かります

**切り替え方法**: ビューアー画面上部のヘッダーにある切替ボタン(オフィス / リモート、縦 / 横)でいつでも切り替えられます。現在の状態を引き継いで表示が切り替わり、選択は URL に同期されるためリロードしても保持されます。

URL パラメータで初期表示を指定することもできます。

```
http://127.0.0.1:3777/?mode=remote                    # リモート(縦)
http://127.0.0.1:3777/?mode=remote&layout=horizontal  # リモート(横)
```

モックプレビューでも「表示設定」の同じボタンで切り替えられます。

## 仕組み

```
Claude Code ──(Hooks)──> report.js ──(HTTP POST)──> server.js ──(WebSocket)──> ブラウザ(PixiJS)
```

1. Claude Code の Hooks(PreToolUse / PostToolUse / SessionStart / UserPromptSubmit / SubagentStart / SubagentStop / Stop / SessionEnd)が `report.js` を起動
2. `report.js` がイベントを `http://127.0.0.1:3777/event` へ POST(サーバー停止中は即座に静かに終了し、Claude Code を一切ブロックしません)
3. `server.js` がエージェント状態をメモリ上で管理し、WebSocket で全クライアントへ配信
4. ブラウザが PixiJS でオフィスとキャラクターを描画

**サブエージェントの動き**: Hook イベントにはサブエージェントの中で発火したことを示す `agent_id` が付きます。これを使って「どのエージェントがそのツールを実行したか」を判別しているため、サブエージェントも自分の担当部屋へ移動して作業します(並列に複数動いても取り違えません)。入室は入口の**カタパルト**からの射出で、残像を引きながら減速して持ち場に着きます(入口から司令席まで 1.2 秒)。**仕事を終えると司令席へ寄ってメインエージェントへ報告し**(頭上に DONE が出て、同時に作業報告カードが出ます)、6 秒後にハッチへ歩いてフェードします。

サブエージェントが終わったことを示す `SubagentStop` は、**どのサブが終わったかを特定できたときだけ**退室させます。特定できないときは誰も退室させず、その場に残った側は 60 秒後に手待ち状態へ落ちます。**消し間違えて、まだ動いているエージェントを画面から消してしまうより安全**だからです。

**途中で止めたとき**: 作業を ESC で中断したりセッションを閉じたりすると、動いていたサブエージェントの `SubagentStop` は**そもそも飛んできません**。そのままだと終わったはずのエージェントが画面に残り続けるので、2 つの受け皿で片付けます。

- 中断したことがそのエージェントの記録に残るので、それを読んだ時点で退室させます(セッションを続けていても、止めた直後に画面から消えます)
- セッションが終わったとき(`SessionEnd`)に、まだ残っているエージェントをまとめて退室させます

作業報告カードには**何を頼まれた人だったか**も出ます。どちらの場合も、中断されたぶんは**「(中断)」付きで出します**。実績が途中までなので、黙って消したり通常どおりの体裁で出したりすると「短時間で終わった」ように読めてしまうためです。

**複数のプロジェクトを同時に見る**: Hooks の設定は Claude Code 全体に効くため、別々のプロジェクトで同時に作業していても**1 つのビューアーにまとめて表示されます**(サーバーは 1 つだけ起動しておけば大丈夫です)。

- **ボス(メインエージェント)はプロジェクトごとに 1 体**います。稼働時間・ツール回数・モデル・トークンもそれぞれ別に出ます
- ボスが 2 体以上いるときは、**全員の名札の 2 行目にプロジェクト名**(作業ディレクトリの末尾)が出るので、どのサブエージェントがどのプロジェクトのものか分かります。リモートモードでは名前のすぐ下の行に出ます。プロジェクトが 1 つだけのときは表示されません。サブエージェントの所属は**そのサブを起動したボスと必ず同じ**になります(自分がどこで動いたかではなく、どのボスの部下かを出します)
- **ボスの機体色はセッションごとに変わります**(下半分の色。白い装甲とオレンジの足はそのままなので「手足のある白い機体 = ボス」という見分け方は変わりません)。掲示板の行頭の丸も同じ色になるので、設定なしでもどのボスがどのプロジェクトか色で追えます
  - ボスが 2 体以上いるときは、**サブエージェントの球体もそのボスと同じ色**になります(オフィスモード・リモートモードとも)。**同じプロジェクトを 2 つ開いていて所属の文字が同じでも、球体の色でどちらの部下か分かります**
  - そのぶん、**同じボスの部下どうしは球体が同じ色**になります。誰が誰かは**名札の名前**と、**掲示板の行頭の丸 / 足元の札の丸**(こちらは今までどおり社員ごとの担当色)、頭上の勲章、立ち位置で見分けてください
  - ボスが 1 体だけのとき(プロジェクトを 1 つしか開いていないとき)は、社員の球体は今までどおり担当色です
- オフィスモードで**同じ部屋にボスが 2 体以上そろうと、まわりの立ち位置が少し外へ広がります**。ボスは頭上の札が高く体も大きいので、ボス 1 体を前提にした並びのままだと、お互いの札で顔が隠れてしまうためです。**ボスが 1 体のときの並びは今までどおり**です
  - **オペルーム**は縦 1 列に並ぶ部屋なので、外へ広げる代わりに **2 体目のボスが手前の列の 2 段目に回ります**。ボスの真下にボスが立つと、上のボスの**名札の 2 行目(プロジェクト名)が、下のボスの頭上の札で隠れてしまう**ためです
- セッションを閉じるとそのボスは退室します。ただし**最後の 1 体は残ります**(オフィスが空になると次に開いたときの入り直しも見えないため)

**プロジェクトごとに色と呼び名を決める**: 各プロジェクトの `CLAUDE.md` に次のブロックを書くと、そのプロジェクトのボスの機体色と呼び名を指定できます。

````markdown
```cva
color: #c4485e
name: アクメ商店
```
````

- `color` は `#rrggbb` / `#rgb`(3 桁・6 桁)に加えて `#rrggbbaa` / `#rgba`(4 桁・8 桁)も指定できます。末尾のアルファ(不透明度)は読み取るだけで反映はせず、RGB だけを使います。読めない値は無視され、既定の色に戻ります。指定した色は、そのボスの**部下(サブエージェント)の球体**にも使われます
- `name` は 12 文字まで(名札の幅の都合で、超えたぶんは切り詰めます)
- 書かなくても構いません。**指定が無いボスはセッションごとの既定色**になります
- `CLAUDE.md` は作業ディレクトリから上へ 6 階層まで探します。編集は 30 秒以内に反映されるので、サーバーの再起動は要りません
- 呼び名の優先順位は `?boss=`(その画面だけの上書き)→ `CLAUDE.md` の `name` → `CVA_BOSS_NAME` → `BOSS` です

**手が空いたとき**: 60 秒イベントが無いと、メインエージェントは**充電ステーション**へ移動し、手足を球体の中へ収めて充電されます(目を閉じ、サブエージェントと同じ真円のシルエットになります)。パッドの光と給電ポストの LED が明滅している間が充電中です。次のツールイベントが来れば通常どおり該当の部屋へ歩いて戻ります。

- **サブエージェントが報告に来ると、充電中でも司令席へ戻ります**。サブエージェントはバックグラウンドで動くのでメインの応答は先に終わっており、「サブが報告に来るときメインは充電中」はよくある状況です。戻るのは**そのサブと同じセッションのメイン**だけで、別の部屋で作業中のメインは引きはがしません
- 充電に入るまでの秒数は `npm start -- --idle=10` / 環境変数 `CVA_IDLE_SEC` / `.env` の `CVA_IDLE_SEC` で変えられます(既定 60 秒)

**あなたの返事を待っているとき**: Claude Code が選択肢つきの質問(`AskUserQuestion`)を出すと、そのキャラクターは司令席で頭上に **ASK** の札を出し、耳と首を振って待ちます。**回答するまで札は出たまま**で、60 秒経っても充電ステーションへは移動しません(席を外している間に気付けるようにするためです)。あなたが答えた時点で通常の状態に戻ります。サブエージェントが質問した場合も、そのサブのキャラクターに札が出ます。

なお、**ツールの実行許可を求めて止まっている**場合は札が出ません。Claude Code はそのとき別の通知(`Notification`)を出しますが、「許可待ち」なのか「入力待ちのアイドル通知」なのかをビューアー側で見分けられず、質問していないのに札が出続けてしまうため、あえて拾っていません(詳細は [DESIGN.md](./DESIGN.md) 4.3)。

**Git の見分け方**: Bash のコマンドが `git` のときは**司令席**へ移動し、頭上のチップが **GIT** になります。単語の切れ目で見ているので `git-cliff` や `gitk` では移動しません。**`gh`(GitHub CLI)は通信管制室のまま**です — 名前のとおりリモートへ繋ぐためです。

**E2E の見分け方**: ブラウザを操作する MCP(`chrome-devtools` / `playwright` / `puppeteer` など)と、`playwright` / `cypress` / `selenium` / `webdriver` / `testcafe` / `e2e` を叩く Bash を **観測ブリッジ**へ送ります。**プロジェクト固有のラッパー(`npm run verify` のような名前)は拾いません** — `verify` のような語まで拾うと、lint や型チェックを走らせているだけの場合に誤検出するためです。判定させたいときは npm script 名や引数に `e2e` を入れてください。

**リモート接続の見分け方**: Bash 系のツールは、コマンドの中身が `ssh` / `scp` / `sftp` / `rsync` / `kubectl` / `gh` / `docker -H` で始まるときだけ**通信管制室**へ移動します(それ以外の Bash は今までどおりオペルームです)。単語の切れ目で見ているので `ssh-keygen` のような別のコマンドでは移動しません。判定にはコマンド本文の**先頭 200 文字**を使うので、それより後ろにある `ssh` は拾えません。吹き出しに出る説明文ではなく**コマンドそのもの**を見ているので、「`ssh` の設定ファイルを見る」のようにコマンドはローカルなのに説明文に `ssh` が入っている場合は移動しません。MCP ツール(`mcp__*`)はローカルで動くものも多いため、リモート扱いにはしていません。

**接続先と作業ディレクトリ**: 通信管制室にいる間だけ、「どこへ繋いで、どこで作業しているか」を出します。

- オフィスモードでは**そのキャラの名札の下**に小さな札が出て、1 行目に接続先(`user@host:/path`)、2 行目にローカルの作業ディレクトリを表示します。行頭の丸は掲示板の行頭と同じ担当色です。同じ部屋で何人も繋いでいるときは、札が重ならないよう **1 段ずつ下にずれます**(札は本人の真下に出たままです)。リモートモードでは同じ内容がタイルの情報行(モデル・経過の下、直近の動きの上)に出ます
- 接続先の読み取り方はコマンドごとに違います。`ssh` / `scp` / `sftp` / `rsync` は最初の非オプション語(`user@host` または `host:path`)、`kubectl` は `--context`(指定が無ければ `kubernetes`)、`docker` は `-H` / `--host`、`gh` は `github.com` です
- **リモート側の作業ディレクトリは取得できません**。ssh は 1 コマンドごとに接続が切れるため、「いまリモートのどこにいるか」という状態がそもそも存在しないからです。コマンドに `cd /path` と書かれていれば、そのパスだけは接続先に添えます
- 表示している作業ディレクトリは**ローカル**(Claude Code を動かしているマシン)のものです。ホームディレクトリは `~` に畳んだ短縮形にし、長い場合は先頭を `…` にして末尾の階層だけ残します。サーバーは 127.0.0.1 にしか bind しないため、このパスが外部へ出ることはありません(同じ PC の他の OS ユーザーからは見えます。下記「セキュリティ」)
- 接続先が拾えないこともあります(ビューアーへ届くのはコマンドの先頭 200 文字なので、それより後ろにあるホストは見えません)。そのときは**何も出しません** — 推測で埋めると、画面に出ているホスト名が本当の接続先とは限らなくなるためです
- 別の部屋へ移ると消えます(上記のとおり「接続中」という状態が無いため、他の部屋で出し続ける意味がありません)

**モデル・エフォート・稼働時間**: 誰がどのモデルで動いているかを、両モードで見られます。

- **オフィスモード** — 壁の左上に掲示板が出て、**1 行 1 人**で名前・モデル/エフォート・経過時間・トークンを表示します。行頭の丸はそのキャラの担当色(足元の札の丸と同じ色)なので、どの行が誰かは色で結び付けられます。項目の位置は全行でそろい、8 人まで同時に並びます(9 人以上は最後の行が「ほか N 件」になります)。取れていない項目は空欄になり、誰の情報も取れていないときは掲示板ごと消えます
- **リモートモード** — 各タイルに、そのエージェントのモデル/エフォート・経過時間・トークン・直近の動きが出ます。タイルが狭いときは後ろの項目から省かれます

どちらのモードでも、出る数字は**そのエージェント 1 人ぶん**です(セッション全体の合計は表示しません)。

表示の元になる値は次のとおりです。**記録ファイルを読むのはサーバーだけ**で、Hook から呼ばれる `report.js` はイベントを転送するだけです(Claude Code をブロックしない設計は変わりません)。

- **モデル**は、そのエージェントの記録(トランスクリプト)から**実際に使われた値**を読みます。サブエージェントは 1 体ごとに専用ファイルへ記録されるため、Agent ツールでモデルを上書きして起動した場合でも実態どおりに表示されます
  - 記録がまだ無い / 読めないときだけ、環境変数 `CLAUDE_CODE_SUBAGENT_MODEL` → `.claude/agents/<定義名>.md` の `model:` の順で**推測**します。推測値はオフィスの掲示板に `Opus 5?` のように `?` を付け、文字を薄くして実測と区別します。実際の値が読めた時点で `?` は消えます
  - 実測も推測も取れなければ**表示しません**(それらしい値で埋めません)。`model: inherit`(既定)の定義だけを置いていて記録もまだ無い、という状態が主なケースです
  - 表示名は短く整えます(`claude-opus-5` → `Opus 5`、`claude-haiku-4-5-20251001` → `Haiku 4.5`)。知らない形式のモデル名はそのまま出します
- **エフォート**は Hook のイベントから取得し、記録から読めた場合はそちらで上書きします(どちらも実測なので新しい方を採ります)
- **トークン**はトランスクリプトから集計します。読めなければ表示しません
  - メインもサブも**1 体ずつ**集計し、オフィスの掲示板ではその人の行、リモートではその人のタイルに `入◯/出◯` の形で出ます
  - 集計はファイルの**末尾 512KB ぶん**だけを対象にします。長時間のセッションでは実際の累計より小さい値になります
- サブエージェントが**司令席で報告を始めると**、オフィスモードに**作業報告カード**(作業時間・ツール実行回数・設定)が数秒出ます。カードの中身がそのまま報告の内容にあたります(司令席に立っている 6 秒は作業時間に数えません)

これらはメモリのみで保持するため、サーバーを再起動すると集計は 0 に戻ります。

## トラブルシューティング

- **キャラクターが動かない**: サーバー(`npm start`)が起動しているか、`npm run setup-hooks` 実行後に Claude Code を再起動したかを確認してください
- **画面上部に「接続待ち…」と表示される**: サーバーとの WebSocket 接続が切れています。3秒間隔で自動再接続します
- **ポート 3777 が使用中**: 他のプロセスが使用していないか確認してください
- **ブラウザに `Forbidden` と出る / 「接続待ち…」のまま繋がらない**: `http://127.0.0.1:3777`(または `http://localhost:3777`)以外のアドレス(PC のホスト名・別名のドメインなど)で開いていないか、`index.html` を file:// で直接開いていないかを確認してください。悪意ある Web サイト対策として、それ以外からの接続は断っています(下記「セキュリティ」)。VS Code Remote などのポート転送で別のポート番号(例: 3777 → 3778)に付け替えられていると、`Host` ヘッダが一致せず 403 になります。転送元と同じポート番号で開くか、`CVA_PORT` をそろえてください
- **VS Code の Simple Browser / ポート転送パネルの「Preview in Editor」で画面が真っ白 / 表示されない**: ビューアーは埋め込み(iframe)を一切許可していないため、エディタ内蔵の webview で開く方法では表示できません。通常のブラウザのタブで `http://127.0.0.1:3777` を開いてください
- **サブエージェントの名札が英字の定義名のまま出る**: 表示名の指定が見つからなかった状態です。サーバーのログに次の1行が出ているか、`http://127.0.0.1:3777/state` の `stats.unmappedAgents` に定義名が載っているかを確認してください(載っていれば「指定し忘れ」、載っていなければ「指定が効いている別の場所がある」と切り分けられます)

  ```
  表示名の読み替えがありません: statusline-setup(定義名をそのまま名札に出します。.claude/agents/statusline-setup.md に displayName: を書くか、.env の CVA_AGENT_NAMES に追加してください)
  ```

  - `displayName:` を書いたのに変わらない場合: 定義ファイルの書き換えは**サーバーを再起動しなくても次のイベントで反映されます**(更新日時を見て読み直します)。変わらないときは `.env` の `CVA_AGENT_NAMES` に同じ定義名が残っていないか(そちらが優先されます)確認してください。優先された場合はサーバーのログに次の1行が出ます

  ```
  表示名は .env の CVA_AGENT_NAMES を優先しました: renderer-dev → 上書き太郎(定義ファイルの displayName: アムロ は使われません)
  ```

  - 新しく**作った**定義ファイル(それまでどこにも無かった定義名)が反映されるまでは数秒かかることがあります。名札は次のイベントで切り替わります
- **モデル名が出ない / `?` が付いたまま**: 起動直後は記録がまだ無いため、数秒待つと実際の値に変わります。それでも変わらない場合は、使用中の Claude Code がサブエージェント専用の記録(`~/.claude/projects/<プロジェクト>/<セッションID>/subagents/`)を出さないバージョンです。`.claude/agents/<定義名>.md` に `model:` を書いておけば推測値(`?` 付き)として表示されます
- **Claude Code を閉じたのにボスが画面に残っている**: しばらく待つと消えます。`/exit` で閉じたときは Claude Code から終了の通知(`SessionEnd`)が飛んでこない(Claude Code 側の既知の不具合)ため、ビューアーは実行中のセッションが置かれるディレクトリ(`~/.claude/sessions/`)を定期的に見て、閉じたことに気付きます。見回りの間隔があるうえ、読み損ねで動いているセッションを消してしまわないよう慎重に確かめるため、**消えるまで最大 120 秒ほどかかります**
  - **開いていたセッションを全部閉じたときは、最後のボスが残ったままになります**。オフィスが無人になるのを避けるため、意図的にそうしています。次のセッションを開いた瞬間に、新しいボスと入れ替わります
  - Claude Code が**クラッシュした**ときは、上記のディレクトリに残骸のファイルが残ります。ビューアーからは「まだ動いている」ように見えるため、そのボスは**次に Claude Code を起動するまで**消えません(起動時に Claude Code 自身が残骸を片付けます)

## セキュリティ

- サーバーは `127.0.0.1` にだけ bind し、外部への通信も、ディスクへの保存(永続化)もしません。状態はメモリにだけあり、サーバーを止めれば消えます
- **画面と WebSocket(および `http://127.0.0.1:3777/state`)には、Claude Code の作業内容の要約が載ります**。主なものは次のとおりです
  - ツール名と、その入力の先頭 80 文字(Bash なら説明文、説明文が無ければコマンド。ほかにファイルパス・検索パターン・検索語・URL など)
  - サブエージェントへの指示の冒頭(掲示板の「作業」と作業報告カード)
  - `ssh` / `kubectl` などの接続先と、コマンドに書かれた `cd` のパス
  - 作業ディレクトリ(短縮形)とプロジェクト名、`CLAUDE.md` に書いた呼び名
  - セッション ID、エージェントの定義名と名札、モデル・エフォート・トークン数・ツール実行回数・経過時間

  **画面共有や配信の最中にビューアーを映すときは注意してください。** なお、あなたが Claude Code に打ち込んだ指示(プロンプト)の本文は送っていません
- **悪意ある Web サイトからの接続は拒否します**。ブラウザで別のサイトを開いていると、そのページから `127.0.0.1` のサーバーへ接続を試みられることがあるため、次の検査をしています
  - `Host` ヘッダが `127.0.0.1:<ポート>` / `localhost:<ポート>` 以外のリクエストは 403(DNS リバインディング対策)
  - WebSocket と `POST /event` は、`Origin` が付いていれば自分のオリジン(`http://127.0.0.1:<ポート>` / `http://localhost:<ポート>`)以外を 403(盗み見・偽イベントの注入の対策)。`Origin` の無い接続(`report.js` などブラウザ以外)は通します
  - このため、`public/index.html` を file:// で直接開いてサーバーへ繋ぐ使い方はできません。ビューアーは必ず `http://127.0.0.1:3777` から開いてください(file:// で開けるのはサーバー不要のモックプレビュー `preview/artifact-preview.html` です)
- **ビューアーのページ自体にも制限を掛けています**。サーバーが返す応答に `X-Content-Type-Options: nosniff` を付け(ブラウザに中身から種類を推測させない)、ビューアーの HTML には Content-Security-Policy を付けています
  - ページが読み込めるのは、同じサーバーのスクリプト・スタイル・画像と、このサーバーへの WebSocket だけです。どのページからの埋め込み(iframe)も禁止しています(同じオリジンやエディタ内蔵のプレビューも含みます)。そのため VS Code の Simple Browser や「Preview in Editor」(ポート転送パネルから webview 内の iframe で開く方法)では表示できません。通常のブラウザで `http://127.0.0.1:3777` を開いてください
  - 描画ライブラリ(PixiJS v7)の都合で、スクリプトの `eval` だけは許可しています。詳細は [DESIGN.md](./DESIGN.md) 4.2「セキュリティヘッダ」を参照してください
- **同じ PC の他の OS ユーザーからは見える・送れる**: `127.0.0.1` はその PC にログインしている全ユーザーから到達できます。共有 PC やマルチユーザー環境では、他のユーザーがビューアーの内容を読んだり、偽のイベントを送ったりできます。localhost の仕組み上避けられないため、**共有 PC では使わないでください**
  - また、ビューアーを止めている間に他のユーザーが同じポートで待ち受けると、`report.js` が送る作業内容の要約がそちらに届きます
- 自前の送信側から `POST /event` を叩くときの受け付け条件(`Content-Type` など)は [DESIGN.md](./DESIGN.md) 4.2 を参照してください
- 脆弱性を見つけたら、[SECURITY.md](./SECURITY.md) の手順で報告してください

## 開発

開発フロー・アーキテクチャの詳細は [DESIGN.md](./DESIGN.md) を参照してください。

- テスト・起動補助はすべて Node.js スクリプト(`.mjs`)で実装しています(`.sh` / `.bat` / `.ps1` なし)
- サーバー側の依存は Node.js 標準ライブラリ + `ws` のみです
- 見た目の開発は `npm run build:artifact` で生成されるモックプレビューで行えます(サーバー・Hooks 不要)
- ブラウザのタブに出るアイコンは `public/favicon.svg`(ボスのハロ)です。`public/character.js` から寸法を写した手書きの SVG なので、キャラクターの造形を変えても自動では追従しません(詳細は [DESIGN.md](./DESIGN.md) 4.26)

### 見た目の検証(`npm run verify`)

実ブラウザ(ヘッドレス)を起動して描画を実測します。検証用の一時サーバーは別ポート(既定 3899)で立てるため、`npm start` で起動中のサーバーには影響しません。

- **Chrome か Edge が入っていれば、ブラウザの追加インストールなしで動きます**(`npm install` で入る `playwright-core` で駆動し、実行ファイルは OS 標準のインストール先から自動で探します)
- どちらも無い環境では、環境変数 `CVA_CHROMIUM` に実行ファイルのパスを指定してください

```powershell
# Windows (PowerShell)
$env:CVA_CHROMIUM = "C:\Program Files\Google\Chrome\Application\chrome.exe"; npm run verify
```

```bash
# macOS
CVA_CHROMIUM="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npm run verify
```

**注意**: ブラウザ(または `playwright-core`)が見つからないときは、理由を表示して**成功扱いで終了します**(見た目の検証は任意という設計のため)。エラーなく終わっても実際には何も検証していないことがあるので、出力に検証結果の一覧(`OK` / `FAIL` の行と「合計 N 件 / 失敗 N 件」)が出ているかを必ず確認してください。
